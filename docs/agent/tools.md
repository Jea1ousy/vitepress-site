# 01 · 工具基座与智能体编程

智能体最终要在一个真实环境里干活：读写文件、运行命令、提交代码。**环境越熟，你越能判断它做得对不对、卡在哪里。** 本篇以 [Missing Semester（2026 版）](https://missing-semester-cn.github.io/)为主线。这门 MIT 一月短课在 2026 版里没有单独的 AI 讲座，而是把 AI 工具融入每一讲——工具课本身正在被智能体重写。

## 为什么智能体时代更要学命令行

**智能体最常用的执行环境就是 shell，而验收它的工作靠的是同一套工具。**

- **搭反馈回路：** 能跑的测试、类型检查、lint 都长在命令行里。给智能体接上这些回路，它才能"跑一遍 → 看报错 → 自己修"。
- **验收工作：** `git diff`、构建输出、日志是你审查智能体产出的主要界面。
- **随时接管：** 智能体在循环里打转时，人直接用命令行定位，通常比继续对话更快。

## 智能体编程：把模型接进反馈回路

### 智能体到底在做什么？ {#how-agents-work}

编程智能体是**带工具访问权限的对话式模型**：读写文件、搜索网页、运行 shell 命令，可以住在 IDE 里，也可以是独立的 CLI/GUI 工具。框架把完整对话历史随每轮请求传入，把模型输出中符合协议的部分解释为工具调用，把执行结果回填给模型，直到它认为任务完成。

**一个最小可用的工具调用智能体只需要约两百行代码。** 复杂度不在"调用模型"，而在工具接口设计、上下文管理和安全边界——这正是后续几篇的主题。

### “实习生”心智模型 {#intern-mental-model}

**把智能体当作一名能力不错、需要监督的实习生。** 它能完成琐碎工作、提高速度，但会犯错、需要明确指示、偶尔要纠正。你不会让实习生直接往生产分支推送，同样也不该无条件接受智能体的产出。

这个模型还暗示了授权的边界：**确认机制不是障碍，是护栏。** 框架默认在执行有破坏性的工具调用前请求确认，省掉确认的前提是搭好沙盒和回滚手段。

### 哪些任务适合交给智能体？ {#use-cases}

| 任务 | 为什么适合 | 关键前提 |
| --- | --- | --- |
| 实现新功能 | 规范明确时收益最大，测试驱动开发效果尤其好 | 先有接口约定和测试 |
| 修复 bug | 能复现、能跑失败用例，就有自我迭代的回路 | 环境可复现 |
| 重构 | 机械变更加全量验证 | 测试保护先到位 |
| 代码审查 | 读取密集、输出结构化 | 明确审查清单 |
| 理解陌生代码库 | 只读不写、容错高 | 结论仍需人工验证 |

规范制定是门艺术，**把自然语言需求翻译成可验证的规格，是人在这条链路里最不可替代的工作。**

### 高级模式：并行、Skills 与子智能体 {#advanced-patterns}

- **并行智能体：** 多个智能体同时跑慢任务时，用 `git worktree` 给每个任务独立工作区，避免互相覆盖修改；合并仍由人把关。
- **Skills 取代一次性提示词：** 可复用的提示词正在被结构化的 Skill 机制取代——名称和描述常驻上下文，正文按需加载。
- **MCP 连接外部工具：** 开放协议把数据库、文档服务等接进智能体，详见[工具生态与 MCP](./mcp)。
- **上下文管理三件套：** 手动或自动压缩（compaction）摘要历史；`AGENTS.md` / `CLAUDE.md` 承载常驻项目约定；子智能体隔离研究类任务的中间上下文，只把结论带回主对话。详见[上下文工程](./context)。

课程给出一道有代表性的练习：让智能体做代码检查子智能体——对自上次提交以来变更的文件运行 `mypy` 和 `ruff`，产出一份结论清单。

### 安全、隐私与沙盒 {#safety-privacy}

::: warning AI 会犯错，且验证有时比编写更难
LLM 本质是概率性的下一词预测器。要审查输出的正确性与安全性；关键代码建议手写。警惕死循环（反复重试同一失败路径）和过度依赖。
:::

- **沙盒：** 在容器或虚拟机里跑"免确认"模式，把破坏限制在可丢弃的环境里。
- **隐私：** 多数托管工具会把大量上下文发往云端，某些场景下供应商可能获得代码库副本与交互记录。敏感代码优先考虑本地或自托管方案，并核数据政策。
- **确认策略分级：** 只读操作自动放行、写入需确认、破坏性操作禁止，比一刀切更可持续。

### 追问：有了智能体还需要学命令行吗？ {#still-need-shell}

**不需要背，但必须读得懂。** 你要能看出一次 `git rebase` 的结果对不对、日志里哪一行才是真正的报错、构建脚本为什么在 CI 上挂了。**工具基座决定智能体的上限：它干不了你验收不了的活。**

每讲配套练习见课程原文；本站的 [Codex 从 0 上手](/codex-from-zero)与[日常工作流](/codex-workflow)就是同一套思路在一个具体工具上的实例。
