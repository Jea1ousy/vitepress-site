# 07 · 评估、后训练与持续进化

没有评估，智能体工程就只是调感觉。**先能度量，再谈优化；先有小评估集，再谈大系统。** 本篇对应《深入理解 AI Agent》第 7—9 章，也是整本书方法论里最该先落地的一章。

## 没有评估，就没有工程

直觉驱动的迭代无法归因：这次变好是提示词改对了，还是样本恰好简单了？评估把"感觉变好"变成"指标变好"。

### 一个最小评估集怎么搭？ {#minimal-eval}

作者的建议很具体：**先建十几条真实任务的小评估集，围绕失败用例迭代。**

1. 从真实使用里挑任务，覆盖典型场景和高频失败。
2. 每条任务写清输入与验收标准——能自动判分最好，不能就写评分细则。
3. 每次改动跑一遍，**把失败用例留下来**，评估集随失败生长。
4. 评估集本身版本化，改动有记录，结果才可比。

### 指标与统计显著性 {#metrics}

- **任务级指标：** 通过率是基本盘；有步数、token 成本、时延等成本指标配合，"通过但贵十倍"要能看出来。
- **分布比均值重要：** 用分位数（P50/P95）和失败案例画像看长尾，均值会藏住最痛的那批失败。
- **小心小样本：** 十几条任务上 60% 到 70% 的波动可能只是噪声。**同一评估集、同一条件下对比**；结论要推到大样本前，先扩样本再下判断。
- **警惕污染：** 评估任务若已进过训练数据或被反复用于调参，分数会虚高。留一部分"只评不改"的封存集。

### SFT 还是 RL？ {#sft-vs-rl}

模型后训练有两个主要手段，选择取决于你能拿到什么数据：

| 维度 | SFT（监督微调） | RL（强化学习） |
| --- | --- | --- |
| 需要的数据 | 高质量示范（输入 → 理想输出） | 可验证的奖励信号（对/错、过测试） |
| 适合 | 固化风格、格式、流程 | 提升决策与试错：何时调工具、失败后怎么改 |
| 成本 | 相对低，上手快 | 高，需要环境与算力 |
| 风险 | 模仿上限，学不到"为什么" | 奖励作弊、过拟合评估 |

一个书里反复强调的区分：**RL 内化的是"何时调用工具"的决策策略，工具的执行仍然在外部基础设施里。** 模型学会的是决策，不是把搜索引擎装进权重。

### 从轨迹中持续进化 {#trajectory-learning}

智能体每跑一次都留下轨迹，轨迹是免费的学习信号。按更新成本从低到高，四个可更新的对象：

1. **知识：** 高频失败的根因写成文档、技能或 `AGENTS.md` 规则——不重训、立即生效。
2. **指令：** 改系统提示与流程编排，成本低，回归风险小。
3. **程序：** 改 Harness 与工具实现，工程量大但可测试。
4. **参数：** 后训练，效果最深、成本与风险最高。

**日常落地优先前两档：** 把重复出现的问题固化成规则与技能，一周见效；后两档留给真正稳定且量大的需求。本站 [Codex 工作流](/codex-workflow)里的项目规则沉淀，就是第 1 档的最小实践。

### 追问：评估集会过拟合吗？ {#eval-overfit}

**会，而且和模型过拟合同构。** 反复围绕同一批失败用例改提示，就是在对评估集调参。对策：封留集定期回测、评估任务定期换血、区分"修 bug"（对着失败改）和"刷分"（只改通过的那条）。**评估集是仪表盘，不是优化目标本身。**
